# 分身与工具权限

一个运行器可以作为多个协作成员使用。例如一个 Claude Code 接入下创建“需求评审”和“代码开发”：前者负责发现需求歧义并输出评审问题，后者负责实现与验证。它们在群内拥有不同身份，可以互发消息、分配任务和交付结果，也可以分别接收人的指令。

## 创建和使用

1. 在“智能体”中完成来源接入配置，点击其卡片上的“创建分身”。
2. 选择初始设定：需求评审、代码开发、测试验证或自定义。预设只是可编辑的起点；填写名称、职责与工作说明。
3. 按需选择工具策略和专用工作目录。默认跟随来源成员的工具策略，默认使用协作空间的工作目录。
4. 新建协作或编辑已有协作，把多个分身同时选入，指定一名队长即可。

每次执行都会附带该成员自己的工作说明；修改说明从下一次执行生效。旧原生会话仍保留，如需清空上下文，在协作的成员面板选择“新建会话”。不同分身共用运行器安装、登录/模型配置和能力，不会自动生成新的平台账号。独立会话也不会自动隔离工作文件；需要并行修改同一个工程时可分别指定工作目录。

## 设置权限

“设置 → 配置权限”提供全局默认与成员覆盖；智能体卡片上的盾牌和工具确认弹窗内的“工具权限”可以直接调整成员。

| 选项 | 行为 |
|---|---|
| 跟随全局 / 来源成员 | 普通成员跟随全局，分身跟随来源；后者仍可单独覆盖 |
| 由我确认 | 运行器上报工具确认请求后，在“待我处理”等待你答复 |
| 自动允许 | 放行运行器提交的工具确认请求，运行记录保留策略决定 |
| 自动拒绝 | 拒绝运行器提交的工具确认请求，Agent 收到拒绝结果 |

保存后立即应用于后续请求及当前等待中的请求，不清空会话。人类已经作出的本次答复不会被策略更新覆盖。

这是**确认请求策略**：原运行器自己的允许/禁止规则、操作系统权限和平台权限仍然有效；已被原运行器自动允许、未上报工作台的操作不会由这里重新审核。协作工具仍受成员身份与领域权限校验。工具策略不自动回答业务问题，也不自动通过已有的交付审核。

交付审核单独设置：权限页的默认选项只影响新建协作；已有协作在“协作设置”中修改“成员交付后由我审核”。业务提问始终需要人答复。

## 各接入能力

| 接入 | 分身 | 工具确认 | 验证边界 |
|---|---|---|---|
| Claude Code | 开放 | 工作台策略 + 原生规则 | 本机真实双分身各三轮，独立记忆及真实同伴回复通过 |
| DeepSeek / ACP | 开放 | ACP permission 请求交给工作台 | ACP 协议夹具通过；本机 DeepSeek 缺模型凭据 |
| CCU Agent | 开放 | 原内核审批回调交给工作台 | 原 CCU 内核与模型夹具已验证；真实模型配置尚未连通 |
| MATLAB Agent | 开放 | 原工具分类与审批桥接 | 既有真实单成员协作已验证；每个分身另启进程，多实例受机器资源与许可证限制 |
| 腾讯 ADP | 条件开放 | 由平台管理 | 当前通过本地请求/流协议测试，未调用公司应用 |
| 通用 HTTP / 单次命令 / 外部系统 | 未默认开放 | 由原系统管理 | 原系统可自行创建不同成员，通过 MCP/HTTP/SDK 分别接入 |

ADP 官方 v2 对话接口声明了 `ConversationId` 独立会话和 `SystemRole` 角色指令。只有确认公司已发布应用支持该字段后，才在 ADP 设置中勾选“应用支持 SystemRole 角色覆盖”。填写角色会覆盖该次调用的应用默认角色设定；分身继续使用同一 AppKey 和原应用能力，不复制工作流、知识库或工具。普通 SSE 文本接口也不会因此获得原生 Teams 工具调用能力。[腾讯官方接口文档](https://adp.tencent.com/zh/document/218682747739893760)

本版按原有接入配置中的 URL 发请求，不自动替换公司端点。腾讯不同产品入口可能使用不同域名，应以公司已发布应用给出的接口地址为准。

## 数据与扩展

配置继续保存在用户目录 `config.json`；分身保存 `source_id` 和自身设定，凭据仍由来源条目引用环境变量或 Windows DPAPI。修改来源程序路径、附加参数、模型配置等会影响它的分身，存在活动运行时拒绝变更。权限修改通过独立管理操作，不受这一停止要求影响。

新增适配器需要显式声明 `profiles` 能力，并验证不同成员的会话隔离；工具审批通过既有 `approve(name, arguments)` 回调统一接入。管理权限只在本机管理 API 暴露，Agent 自身不能创建分身或修改批准策略。具体代码边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。
