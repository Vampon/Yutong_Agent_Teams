# Yutong Agent Teams · 0.3.2

Windows 智能体协作工作台，Python 实现。**协作架构以本地 CCCC 0.4.48 为依据，CCU Agent 仅提供界面风格参考。** 各成员保留自己的模型、工具和会话，通过共享控制服务交换消息、分配任务、维护上下文和请求人类参与。

## 使用

双击发布目录中的 `Yutong Agent Teams.exe`（本次 0.3.2 位于 `dist/0.3.2/`，旧版文件保留）。这是单文件免安装程序，工作台自身无需安装 Python 或 Node.js。目标为 Windows 10/11 x64，需要系统 WebView2 Runtime 与 .NET Framework。Claude、DeepSeek、CCU、MATLAB 仍使用电脑原有的安装、配置和许可证。

1. 在“智能体”中填写程序路径、项目目录或接口配置。“检查配置”只检查本地配置，不代表真实模型已经连通。
2. 新建协作，选择队长、成员、共同目标与工作目录。
3. 向队长或指定成员发送消息。可选“需要回复”或“留信”；留信保留在收件箱，不主动唤起成员。
4. Agent 可在执行中直接调用协作工具，联系同伴、委派任务、提交结果。终端输出与群消息分别保存。
5. 在“待我处理”答复提问、确认工具执行或审核交付。前置交付审核通过后，依赖任务才可执行。
6. 在成员面板查看原生会话状态、停止运行或明确新建会话。遇到不确定投递，先核对实际结果，再选择重发或忽略。

配置和数据默认保存在 `%USERPROFILE%\.yutong-agent-teams`。可用 `--home <目录>` 或 `YUTONG_TEAMS_HOME` 覆盖。不要把测试目录作为日常数据目录。

### 消息与执行过程

0.3.2 修复 DeepSeek Harness Web 与 ACP 模型配置分离的问题：ACP 未单独配置时自动读取 Web 中的提供方及默认模型，复用 Harness 凭据引用；不再把自定义提供方误当成缺少 DeepSeek 官方密钥。成员设置可指定配置来源和模型，“检查配置”显示路由。兼容当前 Harness 的 `session/resume`，同时保留其他 ACP 运行器的 `session/load`。详见 [接入说明](docs/INTEGRATIONS.md)。

- 群聊按控制服务实际保存的顺序显示，时间精确到秒；任务委派使用独立的可展开条目。成员可能先委派、再回复人类，界面保留这个真实顺序。
- 每次执行都有对应的过程卡片：运行中显示成员公开的文字输出、工具输入/结果、等待确认、失败和耗时。结束后自动收起，可展开或打开“查看完整过程”；过程输出不冒充正式群消息。
- Claude、ACP/DeepSeek、CCU、MATLAB、ADP 按各自协议提供可见输出；未提供中途输出的接口只能显示状态及最终返回。工作台不推断未返回的执行结果。当前新增真实验证覆盖 Claude；其他协议及界面验证范围见 [验证记录](docs/VERIFICATION.md)。
- 输入框随内容自动增高，保留 Ctrl + Enter 发送；取消原生拖拽角与蓝色焦点框。后台输出更新时保留草稿、光标和历史阅读位置。

退出旧版后替换 EXE 即可，继续使用原用户目录。旧记录只能展示当时已保存的过程，无法补回未采集的工具结果。

### 工具权限与分身

- 在 **设置 → 配置权限** 选择默认工具策略：由我确认、自动允许或自动拒绝；可为成员单独覆盖。卡片上的盾牌和工具确认弹窗也能直接打开成员权限。保存立即生效，包含正在等待的工具确认。
- 这些策略处理运行器提交到工作台的确认请求，不替代原运行器的权限规则或文件沙箱。业务提问始终保留给人；交付审核单独设置，默认选项只影响新协作，已有协作在“协作设置”调整。
- 在支持的运行器卡片上点 **创建分身**，选择需求评审、代码开发、测试验证或自定义。填写名称、职责、专属工作说明，可选单独权限与工作目录；之后多个同源分身可同时加入一个协作。
- 分身引用来源接入的程序、模型配置与凭据，不复制凭据；每个分身有独立成员 ID、MCP 身份和原生会话。工作说明每次执行都会带入。修改来源接入会影响所有分身；修改已有会话的运行环境后需要明确新建会话。会话独立不等于文件隔离，可以按需指定不同目录。
- Claude / DeepSeek / 通用 ACP / CCU / MATLAB 开放分身。ADP 默认关闭：公司已发布应用确认支持 `SystemRole` 后，可在 ADP 接入设置中开启角色覆盖；它共用原应用的业务能力，不创建或修改平台应用。任意 HTTP、单次命令和外部系统不默认假设支持分身，可在原系统创建独立成员后接入。

真实双 Claude 分身验证已覆盖独立职责、各自多轮记忆、同伴消息与关联回复。ADP 角色覆盖目前仅通过协议夹具，尚无公司应用凭据用于实测。详细使用和扩展边界见 [分身与权限](docs/PROFILES.md)。

0.2.1 修复了内网主机名解码导致的启动失败，以及成员选择复选框撑满卡片造成的错位。Agent 图标随包提供，缺失或加载失败时回退首字头像；列表改为紧凑的 2–4 列布局。应用图标外部已改为真实透明背景。退出旧版后替换 EXE 即可，继续使用原用户目录。

## 本次重构

- 独立成员身份、每个协作成员独立原生会话；统一控制服务拥有协作状态。
- 原生 MCP 协作工具和 HTTP/Python SDK；Claude/CCU/MATLAB 可以在执行过程中调用工具，不再解析最终回复中的 JSON 动作。
- 投递、已读、回复分别记录；支持定向消息、广播、请求回复、不打断成员的留信。
- 唯一持久状态库、只追加的事件记录、幂等发送、任务/共享上下文版本检查、任务依赖、人类交付审核。
- 共享目标、约束、决定、交接记录和成员工作状态。
- 界面增加收件箱、共享上下文、动态和集中待办；已删除顶部重复说明和底部“本地工作台 / 版本号”。
- 本机界面与可选内网 Agent 接入服务分开。远端只持有单个成员凭据，不能操作桌面管理接口。

## 开发与打包

```powershell
python -m pip install -r requirements.txt
python launch.py
python -m unittest discover -s tests -p 'test_*.py' -v
python -m pip install pyinstaller==6.21.0
.\scripts\build.ps1 -Python python
```

原 EXE 正在使用时，可加 `-DistPath dist/0.3.1` 输出到独立目录；验包使用 `python scripts/packaged_check.py --exe "dist/0.3.1/Yutong Agent Teams.exe"`。退出旧版后再运行新版，避免两个版本同时操作日常目录。

前端为按功能拆分的原生 ES modules，无运行时 npm 依赖。Windows 包内含 Python、pywebview、界面资源和桥接脚本。编译环境、测试范围及 EXE 哈希记录在验证文档与 `dist/*.sha256`。

界面色彩统一在 `yutong_teams/web/tokens.css`，沿用 CCU 的中性灰底、白色内容区与深色文字。应用图标将宇通标识与三个互联的 Agent 节点结合；生成原图和提示词见 [assets/brand/prompt.md](assets/brand/prompt.md)。构建脚本自动从原图生成界面 PNG 和 16–256 像素 Windows ICO。

旧版源码备份在 `archives/v0.1-source.zip`。首次启动 0.2 时，旧 `teams.db` 会只读导入新 `collaboration.db`，旧库保持原样；旧协作默认暂停，未完成任务需要人工核对后继续。不要同时让两版操作同一套 Agent 工作目录。

## 范围

本版保留桌面群协作核心；不包含手机端、IM 桥接、语音、云端账号、多用户 SSO、集群高可用、文件自动同步、完整交互终端、A2A 服务端和 CCCC 原生 wire/schema 兼容。跨电脑通过一个中心控制服务接入；不同电脑的文件访问需使用各自工具、共享盘或明确的文件传递方式。

每个成员串行执行，跨成员最多默认 3 路并行；默认每条协作链最多 24 次唤起，2–100 可配置。共享工作目录不会自动获得 Git worktree 隔离。长期上下文管理继续交给原运行器。
